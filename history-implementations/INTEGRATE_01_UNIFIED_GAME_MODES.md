## Player-facing result

On joining the same Roblox experience, players see a responsive **Choose your game mode** screen with three clear buttons/cards:

1. **Factory Challenge** — temporary six-player factory tycoon, owned plots, existing upgrades and shared Supply Cache. **Use walk-over purchases by default**, without tapping/clicking/ProximityPrompt confirmation for regular purchase pads. Walking into a valid pad automatically buys once. Preserve predictable unaffordable/re-entry behavior and server-authoritative proximity, ownership, prerequisites, costs, anti-duplicate protection, UI/modal safety and mobile touch walking. Keep the visible, active purchased machinery and reduced-motion behavior of EXP-02. The shared Supply Cache may retain its deliberate claim interaction. Never silently change the economy catalogue or substitute an auto-buy for all UI actions.
2. **Infinite World** — the account-owned persistent social property, discovery, personalization, arranging/decorating and calm play from INF-01, INF-02, INF-03, MODE-01. Save/rejoin without mixing progress with Factory. No session-only Supply Cache, forced reset or competition. Reuse the repaired ownership/lease/saving/handoff machinery; maintain fail-closed load states. Include PERF-01's measured production geometry-reconciliation improvement where safe. Don't ship debug/showcase fixtures.
3. **Aim Clash** — the standalone osu!-inspired rapid click/tap circles experiment from EXP-03, **not a music-sync rhythm game and not yet a factory combat system**. Provide **Practice** on one account and **Duel queue** for two human players. Keep the shared-pattern server adjudication, escalating speed, combo bonuses and independent Precision percentage, private intermediate scores, terminal winner/score breakdown and touchscreen-safe UI. Do not advertise a broader 6-player battle or embed the clash as a forced factory event.

Each mode has a clearly reachable **Modes / Back to menu** control. From Infinite, the existing safe checkpoint/departure behavior must finish or display an honest error before returning; never discard or relabel unconfirmed progress. From the other two modes, return is non-destructive. Mobile portrait/landscape and keyboard/controller basics should be readable and navigable. Buttons must perform actual entry, not merely hide/show a UI over an unchanged server. Show meaningful Loading / Joining / Unavailable / Retry states for failures or unconfigured places; no click loop, fake successful switch or silently changed server mode. Clear names, compact subtitles, no excessive decorative overlays.

A game mode is distinct from a Roblox **experience**. The final model is **one private development experience** with **four places** in that same universe: current start place becomes Entry/Menu, plus Session, Infinite, and Aim Clash destinations. Each gameplay server runs one trusted role. Reuse MODE-01's server-side place-role validation and TeleportService failure recovery, extended for the duel. Do not let a client-supplied mode name, teleport payload, or mutable user setting decide authoritative server role. Session/Infinite should remain ordinary shared multiplayer servers rather than per-user private instances. Aim Clash should support solo and actual two-user testing in its destination. Return/back also uses trusted server routing. Preserve the existing authored factory map in Session; do not accidentally replace it with a code-only Rojo build.

Do not silently include EXP-01 Parry Lab, which is a separate experimental combat concept not requested in this three-mode integration. Keep it for a later decision.
