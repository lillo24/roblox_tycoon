# Four-place development deployment

This folder owns deployment policy and source-fresh authored-map builds, separate from gameplay and map authoring. Requires PowerShell 7.

- `GameplayArtifact.psm1` reuses the existing gameplay-only scene assembler. `New-DevelopmentPlaces` returns exactly four role/path entries. Each build keeps the saved non-code scene and all current scripts, with one narrowly verified override: generated server `Routing/Settings` containing the validated manifest and expected role. `Assert-DevelopmentPlace` independently reconstructs that override, checks all other source/classes/paths and canonical scene fidelity, rejects links/QA/fixtures and API-limited classes including descendants. `Get-DevelopmentRoutingSource` accepts only all-zero disabled offline config or positive, distinct, exactly representable live IDs. Session maps to the existing internal `Prototype` role.
- `DevelopmentDeployment.psm1` validates manual/main/credentials/all IDs and checkout, runs the complete validator, builds and captures four verified immutable XML buffers/hashes, then verifies same-universe membership/root place with documented public credential-free GETs (bounded pagination). It uploads Session, Infinite, Clash, then Entry; each needs a 2xx positive integer version response. The exact four-role order is checked and copied before callbacks; missing or altered module state fails before validation/build/HTTP, including in dry-run mode. Membership independently requires all four destinations. No redirects, cookies, automatic retries, raw response bodies or raw network exception text. A failure stops subsequent uploads. Confirmed/unknown/unattempted statuses are recorded throughout, without claiming atomic publication or live gameplay success.

The default validator runs `Validate-Project.ps1` with the current PowerShell 7 installation in a separate `-NoProfile -NonInteractive` process. Its nonzero exit code stops deployment before building or HTTP. This process boundary is required: the offline suite imports the publisher under test, and importing it from its own active module scope can rebind script-scoped state in PowerShell. Running the validator in that same process previously let the inner test publisher report completion with zero place records instead of examining its injected fixture. The fixture verifier itself still rejects that XML. The child process prevents re-entry; the four-role preflight independently prevents empty success.

`Validate`, `Build`, `CheckCheckout`, `Transport` and `Record` are trusted test seams; the CLI exposes none. Dry-run deliberately ignores even supplied live IDs/key, builds disabled zero-ID manifests and performs no transport. Live mode cannot use these offline builds.

`../Invoke-DevelopmentDeployment.ps1` reads process environment only and writes allowlisted commit/role/place/hash/version/status fields in a final job summary even on partial failure. The single manual workflow invokes it without overrides. It retains DEPLOY-01's concurrency group, checkout/main restrictions, immutable source checks, key scope and success-only short artifact retention. The extra build/role/executed-Luau checks expand validation time, not workflow frequency; PR validation still has no duplicate main-push run, and manual Validate remains the full checkpoint.

`../Test-DevelopmentDeployment.ps1` uses real fresh builds/mutations and mocked HTTP to cover complete configuration, fidelity, membership, publish ordering, redaction, immutable buffers and partial/ambiguous failures. It rejects fixtures in each of the four release slots before any GET or POST, tests missing/altered order in live and dry-run modes, and exercises the private child-process runner with a publisher-import/fixture probe and a failing validator. The private runner's script-path override is a trusted test seam, unavailable from the CLI. It never calls Roblox or needs credentials. Owner creation, publishing and phone steps are in [MOBILE_DEPLOYMENT.md](../../docs/MOBILE_DEPLOYMENT.md).
